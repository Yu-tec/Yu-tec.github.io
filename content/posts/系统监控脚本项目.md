## 一、第一阶段：手写 MVP（最小可行性产品）

### 目标
- 写一个单文件脚本，硬编码阈值（比如 CPU>80%）
- 用 `vmstat`、`free`、`df -h` 获取数据，用 `awk` 清洗
- 用 `if [ $cpu -gt 80 ]; then ... fi` 做判断
- 用 `echo "告警内容" | mail -s "主题" xxx@qq.com` 发邮件
- 手动执行能跑通后，用 `crontab -e` 设置每分钟执行一次
- 完成度：60 分

### 1. 编写 MVP 脚本 `monitor_mvp.sh`

```bash
#!/bin/bash

# ==========================================
# 系统资源监控 MVP 脚本
# ==========================================

# 1. 硬编码阈值 (可根据自己机器情况修改)
CPU_THRESHOLD=80
MEM_THRESHOLD=80
DISK_THRESHOLD=80

# 2. 接收告警的邮箱 (请换成你自己的邮箱)
ALERT_EMAIL="xxx@qq.com"

# 3. 获取当前时间
NOW=$(date "+%Y-%m-%d %H:%M:%S")

# ================== 数据采集与清洗 ==================

# 获取 CPU 使用率
# vmstat 1 2：采样2次，间隔1秒。第一次是自开机以来的平均值，第二次才是当前真实值，所以用 tail -1 取第二行
# $15 通常是空闲率(id)，100 - id 就是使用率。使用 int() 取整，方便 Bash 做数值比较
CPU_USAGE=$(vmstat 1 2 | tail -1 | awk '{print int(100 - $15)}')

# 获取内存使用率 (使用 free -m 以 MB 为单位)
MEM_TOTAL=$(free -m | grep Mem | awk '{print $2}')
MEM_USED=$(free -m | grep Mem | awk '{print $3}')
# 计算百分比
MEM_USAGE=$(( MEM_USED * 100 / MEM_TOTAL ))

# 获取根分区磁盘使用率
# df -h /：只看根分区。$5 是使用率列（如 45%），tr -d '%' 去掉百分号
DISK_USAGE=$(df -h / | tail -1 | awk '{print $5}' | tr -d '%')

# 打印当前采集到的数据 (方便调试)
echo "[$NOW] 当前监控数据 -> CPU: ${CPU_USAGE}% | 内存: ${MEM_USAGE}% | 磁盘: ${DISK_USAGE}%"

# ================== 告警判断与发送 ==================

if [ $CPU_USAGE -gt $CPU_THRESHOLD ]; then
    echo -e "【警告】$NOW\nCPU 使用率过高！\n当前值: ${CPU_USAGE}%\n阈值: ${CPU_THRESHOLD}%" | mail -s "监控告警: CPU过高" $ALERT_EMAIL
    echo ">>> 已发送 CPU 告警邮件"
fi

if [ $MEM_USAGE -gt $MEM_THRESHOLD ]; then
    echo -e "【警告】$NOW\n内存 使用率过高！\n当前值: ${MEM_USAGE}%\n阈值: ${MEM_THRESHOLD}%" | mail -s "监控告警: 内存过高" $ALERT_EMAIL
    echo ">>> 已发送 内存 告警邮件"
fi

if [ $DISK_USAGE -gt $DISK_THRESHOLD ]; then
    echo -e "【警告】$NOW\n磁盘 使用率过高！\n当前值: ${DISK_USAGE}%\n阈值: ${DISK_THRESHOLD}%" | mail -s "监控告警: 磁盘过高" $ALERT_EMAIL
    echo ">>> 已发送 磁盘 告警邮件"
fi

echo "监控脚本执行完毕。"
```

### 2. 赋予执行权限

```bash
chmod +x monitor_mvp.sh
```

### 3. 手动运行，然后查看日志

```bash
./monitor_mvp.sh
cat /tmp/monitor_mvp.log
```

## 二、邮件发送方案

### 方案一：`mailx`（传统方案，不推荐）

#### 安装邮件客户端

```bash
# CentOS
yum install -y mailx
yum install -y mailx sendmail
```

#### 修改 `/etc/mail.rc` 配置文件

```bash
# 编辑配置文件
vim /etc/mail.rc

# 追加以下内容 (把 xxx 换成你自己的信息)
set from=你的QQ号@qq.com
set smtp=smtp.qq.com:587
set smtp-auth-user=你的QQ号@qq.com
set smtp-auth-password=你的授权码
set smtp-auth=login
set ssl-verify=ignore
set nss-config-dir=/etc/pki/nssdb
```

#### ❓ `mailx` 始终无法稳定连接的原因

在实际配置过程中，`mailx` 反复报错，无法稳定发送邮件，主要原因如下：

1. **SSL/TLS 握手失败（报错 `Unknown error -5938`）**
   CentOS 7 默认的 `mailx` 版本与 QQ 邮箱的 SSL 握手存在兼容性问题，`smtps://smtp.qq.com:465` 无法建立加密连接。

2. **强制要求安全连接（报错 `530 Login fail. A secure connection is required`）**
   QQ 邮箱强制要求 SSL/TLS 加密连接，明文或未加密的 SMTP 会被直接拒绝。

3. **证书校验失败（报错 `Peer's certificate issuer is not recognized`）**
   `nss-config-dir` 指向的 NSS 证书库未能正确验证 QQ 邮箱证书，导致握手中断。

4. **STARTTLS 支持不完整**
   即使改用 587 端口并加上 `set smtp-use-starttls`，CentOS 7 自带的 `mailx` 对 STARTTLS 的实现仍存在缺陷，无法完成握手。

5. **根本原因**
   `mailx` 依赖 NSS 库处理 SSL/TLS，而 CentOS 7 的 `mailx` 版本较老，对现代 SMTP 服务器的加密要求支持不完善。

**结论**：`mailx` 能用，但 SSL/TLS 兼容性差，在 CentOS 7 + QQ 邮箱场景下反复踩坑，**不推荐在自动化脚本中使用**。

#### ✅ 解决方案：换用 `msmtp`

### 方案二：`msmtp`（现代方案，推荐）

#### 1. 安装 `msmtp`

```bash

```

#### 2. 创建 `msmtp` 配置文件

`msmtp` 读取配置文件的顺序是：`~/.msmtprc`（当前用户）或 `/etc/msmtprc`（全局）。

```bash

```

```ini

auth           on
tls            on
tls_starttls   off
tls_trust_file /etc/pki/tls/certs/ca-bundle.crt
logfile        ~/.msmtp.log

account        qq
host           smtp.qq.com
port           465
from           2292537637@qq.com
user           2292537637@qq.com
password       你的新授权码

account default : qq
```

#### 3. 设置权限（必须）

```bash
chmod 600 ~/.msmtprc
```

> `msmtp` 出于安全考虑，如果配置文件是所有人可读，会直接拒绝运行。

#### 4. 测试邮件发送

```bash
echo -e "Subject: msmtp 测试\n\n这是一封来自 msmtp 的测试邮件。" | msmtp 2292537637@qq.com
```

- **没有任何输出** = 发送成功（Unix “沉默即成功”哲学）
- **有报错** = 查看日志 `cat ~/.msmtp.log`

## 三、第二阶段：升级为小型项目

把单文件脚本，升级成一个小型项目：

```text
monitor_project/
├── bin/
│   └── monitor.sh          # 主脚本 (只负责调用函数)
├── conf/
│   └── monitor.conf        # 配置文件 (阈值、邮箱、路径等)
├── lib/
│   └── common.sh           # 公共函数库 (数据采集、发送邮件、日志记录)
└── logs/
    └── monitor.log         # 日志文件 (由脚本自动创建)
```

**最大好处**：主脚本变得极其干净，所有需要修改的东西都放在 `conf` 里，所有核心逻辑都在 `lib` 里。

### 1. 创建目录结构

```bash
mkdir -p ~/monitor_project/{bin,conf,lib,logs}
cd ~/monitor_project
```

### 2. 创建配置文件 `conf/monitor.conf`

```bash
vim ~/monitor_project/conf/monitor.conf
```

```bash
# ========================================
# 监控系统配置文件
# ========================================

# 告警接收邮箱
ALERT_EMAIL="2292537637@qq.com"

# 告警阈值
CPU_THRESHOLD=80
MEM_THRESHOLD=80
DISK_THRESHOLD=80

# 负载阈值系数 (0.8 表示 CPU 核心数的 80%)
LOAD_FACTOR=0.8

# 告警静默期 (秒)，同一指标在 N 秒内只发一次告警
ALERT_INTERVAL=600

# 日志文件路径
LOG_DIR="/root/monitor_project/logs"
LOG_FILE="${LOG_DIR}/monitor.log"

# 告警状态文件目录
STATE_DIR="/tmp/monitor_state"

# msmtp 可执行文件路径
MSMTP_BIN="/usr/bin/msmtp"
```

### 3. 创建函数库 `lib/common.sh`

```bash
vim ~/monitor_project/lib/common.sh
```

```bash
#!/bin/bash

# ========================================
# 公共函数库
# ========================================

# ----------------- 日志函数 -----------------
log_info() {
    echo "[$(date '+%Y-%m-%d %H:%M:%S')] [INFO] $*" >> "$LOG_FILE"
}

log_alert() {
    echo "[$(date '+%Y-%m-%d %H:%M:%S')] [ALERT] $*" >> "$LOG_FILE"
}

# ----------------- 数据采集函数 -----------------
get_cpu_usage() {
    vmstat 1 2 | tail -1 | awk '{print int(100 - $15)}'
}

get_mem_usage() {
    free -m | grep Mem | awk '{print int($3/$2 * 100)}'
}

get_disk_usage() {
    df -h / | tail -1 | awk '{print $5}' | tr -d '%'
}

get_load_avg() {
    cat /proc/loadavg | awk '{print $1}'
}

# ----------------- 告警抑制 + 发送邮件 -----------------
send_alert_with_suppression() {
    local alert_type="$1"
    local subject="$2"
    local message="$3"

    local state_file="${STATE_DIR}/${alert_type}.last"
    local current_time=$(date +%s)

    # 检查状态文件是否存在
    if [ -f "$state_file" ]; then
        local last_time=$(cat "$state_file")
        local time_diff=$((current_time - last_time))

        if [ $time_diff -lt $ALERT_INTERVAL ]; then
            log_info "告警被抑制: $alert_type (距上次告警 ${time_diff} 秒)"
            return 1
        fi
    fi

    # 发送邮件 (msmtp)
    {
        echo "Subject: $subject"
        echo "From: $ALERT_EMAIL"
        echo "To: $ALERT_EMAIL"
        echo ""
        echo -e "$message"
    } | $MSMTP_BIN "$ALERT_EMAIL"

    # 记录告警日志
    log_alert "$subject | $message"

    # 更新状态文件
    mkdir -p "$STATE_DIR"
    echo "$current_time" > "$state_file"

    return 0
}

# ----------------- 通用检查函数 -----------------
check_metric() {
    local name="$1"
    local value="$2"
    local threshold="$3"
    local unit="${4:-%}"

    log_info "$name 当前值: ${value}${unit} (阈值: ${threshold}${unit})"

    if [ "$value" -gt "$threshold" ]; then
        local subject="[$HOSTNAME] 监控告警: $name 过高"
        local message="告警时间: $(date '+%Y-%m-%d %H:%M:%S')\n主机名: $HOSTNAME\n告警项: $name\n当前值: ${value}${unit}\n阈值: ${threshold}${unit}"

        send_alert_with_suppression "$name" "$subject" "$message"
    fi
}
```

### 4. 创建主脚本 `bin/monitor.sh`

```bash
vim ~/monitor_project/bin/monitor.sh
```

```bash
#!/bin/bash

# ========================================
# 系统监控主脚本
# ========================================

SCRIPT_DIR="$(cd "$(dirname "$0")/.." && pwd)"

source "${SCRIPT_DIR}/conf/monitor.conf"
source "${SCRIPT_DIR}/lib/common.sh"

mkdir -p "$LOG_DIR"

HOSTNAME=$(hostname)

log_info "========== 监控脚本开始执行 =========="

# 检查 CPU
CPU_USAGE=$(get_cpu_usage)
check_metric "CPU" "$CPU_USAGE" "$CPU_THRESHOLD"

# 检查内存
MEM_USAGE=$(get_mem_usage)
check_metric "内存" "$MEM_USAGE" "$MEM_THRESHOLD"

# 检查磁盘
DISK_USAGE=$(get_disk_usage)
check_metric "磁盘" "$DISK_USAGE" "$DISK_THRESHOLD"

# 检查系统负载
LOAD_AVG=$(get_load_avg)
CPU_CORES=$(nproc)
LOAD_THRESHOLD=$(echo "$CPU_CORES * $LOAD_FACTOR" | bc)

log_info "系统负载 当前值: $LOAD_AVG (阈值: $LOAD_THRESHOLD, 核心数: $CPU_CORES)"
if (( $(echo "$LOAD_AVG > $LOAD_THRESHOLD" | bc -l) )); then
    SUBJECT="[$HOSTNAME] 监控告警: 系统负载过高"
    MESSAGE="告警时间: $(date '+%Y-%m-%d %H:%M:%S')\n主机名: $HOSTNAME\n告警项: 系统负载\n当前值: $LOAD_AVG\n阈值: $LOAD_THRESHOLD (核心数: $CPU_CORES)"
    send_alert_with_suppression "系统负载" "$SUBJECT" "$MESSAGE"
fi

log_info "========== 监控脚本执行结束 =========="
```

### 6. 引入 expect 实现服务自愈

在监控系统基础上，引入 `expect` 脚本，实现“检测到服务异常 → 自动登录 → 重启服务”的闭环，即“服务自愈”。

#### 6.1 目标

- 当监控脚本检测到 Nginx 服务异常（非 `active`）时，自动通过 SSH 登录目标服务器并重启 Nginx。
- 整个过程无需人工干预。
- 保留日志记录，方便事后排查自愈是否成功。

#### 6.2 安装 expect

```bash
yum install -y expect
```

#### 6.3 创建 expect 脚本

在项目中新建 `scripts` 目录，专门存放 `.exp` 脚本：

```bash
mkdir -p /root/monitor_project/scripts
vim /root/monitor_project/scripts/restart_nginx.exp
```

写入以下内容：

```expect
#!/usr/bin/expect -f

set target_ip   [lindex $argv 0]
set target_user [lindex $argv 1]
set target_pass [lindex $argv 2]

set timeout 30
log_user 1

spawn ssh -o StrictHostKeyChecking=no $target_user@$target_ip

# 登录阶段：兼容 yes/no、password、已登录成功 三种情况
expect {
    "yes/no" {
        send "yes\r"
        exp_continue
    }
    "password:" {
        send "$target_pass\r"
        exp_continue
    }
    -re {[#\$] $} {
        # 已经登录成功，退出 expect，进入下一步
    }
    timeout {
        puts "登录阶段超时"
        exit 1
    }
}

# 重启 Nginx
send "systemctl restart nginx\r"
expect {
    -re {[#\$] $} {}
    timeout {
        puts "重启 Nginx 阶段超时"
        exit 1
    }
}

# 检测状态
send "systemctl is-active nginx\r"
expect {
    "active" {
        puts "Nginx 重启成功"
    }
    "inactive" {
        puts "Nginx 重启失败"
        send "exit\r"
        exit 1
    }
    timeout {
        puts "检测 Nginx 状态超时"
        send "exit\r"
        exit 1
    }
}

send "exit\r"
exit 0
```

check_nginx_and_heal() {
    local nginx_status
    nginx_status=$(systemctl is-active nginx 2>/dev/null)

    log_info "Nginx 当前状态: $nginx_status"

    if [ "$nginx_status" = "active" ]; then
        log_info "Nginx 运行正常"
        return 0
    fi

    log_alert "Nginx 服务异常 (状态: $nginx_status)，触发自愈脚本..."
    "$EXPECT_SCRIPT" "$NGINX_TARGET_IP" "$NGINX_TARGET_USER" "$NGINX_TARGET_PASS" >> "$LOG_FILE" 2>&1

    sleep 2
    nginx_status=$(systemctl is-active nginx 2>/dev/null)
    if [ "$nginx_status" = "active" ]; then
        log_info "Nginx 自愈成功"
    else
        log_alert "Nginx 自愈失败，请人工介入！当前状态: $nginx_status"
    fi
}
```

```

### 本次踩坑记录

在引入 `expect` 实现服务自愈的过程中，遇到三个典型问题，记录如下。

#### 坑 1：expect 脚本缺少“登录成功”分支，导致超时

**现象**：

```
expect: does " ... [root@localhost ~]# " ... match glob pattern "password:"? no
"yes/no"? no
expect: timed out
SSH连接超时
```

**原因**：

`expect` 脚本的第一阶段只匹配 `password:` 和 `yes/no`，没有匹配 `[#\$] $`（Shell 提示符）的分支。当 SSH 登录成功后出现 `[root@localhost ~]#`，`expect` 仍然在等 `password:`，于是空等到超时。

**修复**：

在第一阶段 `expect` 块中加入：

```expect
-re {[#\$] $} {
    # 已经登录成功，进入下一步
}
```

这样无论登录过程是：

- 首次连接弹 `yes/no`
- 需要密码弹 `password:`
- 免密登录直接进 Shell

都能正确识别，进入下一阶段。

#### 坑 2：ssh 检测不会走 expect，会卡在密码输入

**现象**：

```
+ check_nginx_and_heal
++ ssh -o StrictHostKeyChecking=no -o ConnectTimeout=5 root@127.0.0.1 'systemctl is-active nginx'
root@127.0.0.1's password:
```

卡住不动，`ConnectTimeout=5` 也不生效。

**原因**：

`ssh` 的 `-o ConnectTimeout=5` **只对 TCP 连接阶段生效**。一旦 TCP 连接建立，进入**密码认证阶段**，`ssh` 就会一直等用户手动输入密码，**不会自动超时退出**。

而且这一句 `ssh` 是直接执行的，没有走 `expect` 脚本，所以 `expect` 里配置的密码用不上，必须手动输入。

**修复**：

本机测试场景下，把检测步骤改成直接用 `systemctl is-active nginx`：

```bash
nginx_status=$(systemctl is-active nginx 2>/dev/null)
```

只有在**跨服务器自愈**场景下，才需要走 `expect` 脚本，并保证 `expect` 脚本本身也支持“检测 + 重启”两步操作。

#### 坑 3：msmtp 路径写错

**现象**：

```
/root/monitor_project/lib/common.sh:行60: /usr/bin/msmtpi: 没有那个文件或目录
```

**原因**：

`conf/monitor.conf` 里的 `MSMTP_BIN` 被误写成 `/usr/bin/msmtpi`（多了一个 `i`）。

**修复**：

```bash
MSMTP_BIN="/usr/bin/msmtp"
```

用 `which msmtp` 确认实际路径。

#### 经验总结

| 坑 | 根因 | 关键教训 |
|---|---|---|
| expect 超时 | 缺少“已登录成功”的匹配分支 | expect 脚本必须覆盖所有可能的提示符 |
| ssh 卡密码 | 检测逻辑没走 expect，ConnectTimeout 对认证阶段无效 | 需要密码的 ssh 要么走 expect，要么本机直接用 systemctl |
| msmtp 路径错误 | 配置文件手误 | 用 which 命令确认实际路径再写配置 |

## 四、两种邮件方案对比总结

| 对比项          | `mailx`                 | `msmtp` ✅                |
| ------------ | ----------------------- | ------------------------ |
| 配置文件         | `/etc/mail.rc`（安装时自动生成） | `~/.msmtprc`（手动创建）       |
| 文件权限         | 无需特殊权限                  | **必须** `chmod 600`       |
| 日志           | `/var/log/maillog`      | `~/.msmtp.log`           |
| SSL 库        | NSS                     | OpenSSL                  |
| 发信命令         | `mail -s "主题" 收件人`      | `msmtp 收件人`（正文含 Subject） |
| QQ 邮箱 465 端口 | ❌ 握手失败                  | ✅ 完美支持                   |
| 适合脚本自动化      | ⚠️ 兼容性差                 | ✅ 稳定可靠                   |

`mail` 命令的语法
echo -e "邮件正文" | mail -s "邮件主题" 收件人@example.com
- **主题用 `-s` 参数指定**
- **正文从标准输入传入**（通过管道或重定向）
- 邮件头（From、To、Subject）由 `mailx` **自动生成**
- 收件人作为**位置参数**直接写

`msmtp` 命令的语法
{
    echo "Subject: 邮件主题"
    echo "From: 发件人@example.com"
    echo "To: 收件人@example.com"
    echo ""
    echo -e "邮件正文"
} | msmtp 收件人@example.com

- **没有 `-s` 参数**，主题必须写在输入文本里
- **邮件头（Subject / From / To）必须自己手动拼接**
- **邮件头和正文之间必须有空行**
- 收件人作为**位置参数**传入
